## 真实 Codex 验证

执行 `npm run test:live`，使用桌面自带 Codex 运行时 `0.166.0-alpha.6` 和运行时返回的默认模型 `gpt-6.1-sol`。

六项检查：

1. 建立来源对话并写入独有项目代号；创建独立协作分支后，不在新请求中重复该信息，Agent 仍正确回答代号。来源历史可展示，来源与协作线程 ID 不同。
2. 两位成员同时提交自由讨论，未产生额外 Agent 调用。
3. 小王提出缓存有效期 `137 秒`，小李提出按 `tenantId` 隔离。Agent 在一次共同答复中准确使用两位成员的姓名和约束。
4. 第一轮进行中新增 `最多 23 项` 的限制，并排队下一次调用。下一轮在第一轮结束后启动，同时保留旧约束和新限制。
5. 房主明确请求实现功能。Agent 在临时隔离工作区创建 `positive-sum.mjs` 和 `positive-sum.test.mjs`，运行测试；验证脚本再次独立执行，确认两项测试通过。共享任务中包含命令、退出结果等执行证据。
6. 另一位成员通过 HTTP 读取同一个线程的全部新讨论、回复、任务与结果。

运行真实验证脚本后，本地报告 `artifacts/live-verification.json` 会记录测试线程、临时工作区、模型、运行时路径和用量。用量按完整回合的累计差值计算，包含工具循环中的多次模型请求。

本机全局 CLI 为 `0.142.5`，其模型目录与桌面版本不同，曾导致服务拒绝模型调用。当前实现优先选择桌面自带运行时，并允许通过 `GROUPTALK_CODEX_BIN` 和 `--model` 显式指定；没有修改全局登录或配置。

## 浏览器验证

使用两个独立 Chrome 窗口身份，一个通过本机地址、一个通过 `en0` 网卡的局域网地址访问同一服务。

- 加入、实时发言、成员在线状态和房间目标同步。
- 两个窗口均显示同一条真实 Codex 答复，答复使用了双方观点与共同记录。
- 引用回复、添加结论和待确认问题，另一窗口可见；普通成员无法开启房主设置或发起未授权执行。
- 服务重启后自动重连，成员、消息、记录与协作线程恢复。
- 邀请面板默认提供实际局域网地址，并可选择其他网卡；复制的邀请不再指向仅本机可用的环回地址。
- 未配置 Jev 密钥时点击开关，保持关闭并显示说明；基础群聊与点名协作正常。
- 桌面 `1440 × 960`、手机 `390 × 844` 均无横向溢出。长讨论在消息区域内部滚动，输入框底部保持在视口底部。

布局验证数据和截图保存在本地 `artifacts/` 目录，分别为 `ui-verification.json`、`prototype-desktop.jpg` 和 `prototype-mobile.jpg`。

## 验证边界

Jev 当前没有配置密钥，因此尚未验证真实服务的可用性、中文裁决质量或网络延迟。接入密钥后可以重新执行真实验证脚本，再用真实小组讨论评估插话阈值。

局域网入口已在本机通过实体网卡地址验证；未使用另一台物理设备测试网络或防火墙的可达性。运行中的服务面向可信局域网，主机需要保持在线。

当前是文字、单机、单房间原型；不包含附件、语音、公网托管、原桌面对话双向同步或长讨论自动摘要。未提交上下文超过 100,000 字符时明确报错并保留原记录。
